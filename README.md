# topsbottg

Telegram-бот для организации выплат: от регистрации получателей до подтверждения оплаты. Администратор работает через Mini App.

## Возможности

- Регистрация получателей: ФИО, учебная группа, платёжные реквизиты.
- Создание выплат и выбор получателей для рассылки.
- Сообщения и ответы через Telegram.
- Отслеживание статусов и отметка оплаты после перевода.
- История выплат и выгрузка CSV.
- Приглашение администраторов и управление их доступом.

## Mini App

Четыре вкладки: **Создать**, **Выбор**, **Получатели**, **История**.

Владельцы могут найти зарегистрированного пользователя по ФИО или Telegram ID, при необходимости отфильтровать результаты по учебной группе и пригласить его в администраторы. Группа необязательна: пользователи без группы также могут стать администраторами. Получатель подтверждает приглашение в боте.

## Быстрый запуск

```bash
cp .env.example .env
# Заполните настройки в .env
docker compose up -d --build
```

Локально интерфейс доступен по адресу `http://127.0.0.1:18080/miniapp/`.

Для работы Mini App внутри Telegram нужен публичный HTTPS-адрес в `MINI_APP_URL` и прокси на локальный порт `18080`.

## Безопасное включение переписки

При переходе с `MemoryStorage` старые незавершённые FSM-состояния не восстанавливаются. До повторного `/start` пользователя нельзя считать готовым к свободной переписке: сообщение может оказаться реквизитами из прежнего запроса. Новый `/start` сбрасывает состояние и устанавливает доверенный признак в PostgreSQL. Простое наличие FSM-записи (в том числе после нажатия старой кнопки) недостаточно. При этом регистрация, изменение ФИО, группы и платёжных реквизитов продолжают работать независимо от флагов чата.

Порядок для отдельного согласованного включения на production:

1. Применить миграции (`alembic upgrade head`) с обоими флагами `CHAT_INBOX_ENABLED=false` и `CHAT_ENTRYPOINT_ENABLED=false`; выполнить резервное копирование PostgreSQL. Сохранять именованный volume `chat_staging` при любом обновлении.
2. Проверить новое сохранение FSM: зарегистрированный тестовый пользователь отправляет `/start`, вводит и изменяет ФИО/группу, проверяет ввод платёжных данных; платежные реквизиты не должны попасть в историю или журналы.
3. В отдельном обновлении включить `CHAT_INBOX_ENABLED=true`, оставив `CHAT_ENTRYPOINT_ENABLED=false`. Убедиться, что свободные сообщения до нового `/start` игнорируются, после `/start` появляются в переписке, а платёжные данные не перехватываются. Проверить ответ администратора и unread.
4. Лишь после этого включить `CHAT_ENTRYPOINT_ENABLED=true`; проверить наличие кнопки «Написать администратору» после `/start` и входящие/исходящие текст, фото, документы и голосовые с тестовым пользователем. Старым пользователям необходимо повторно отправить `/start`.
5. Если приём или отправка работают некорректно, установить оба флага в `false` и пересоздать только контейнер `app`. Не удалять PostgreSQL и `chat_staging`: queued-задания и история должны сохраниться до устранения проблемы.

Флаг `CHAT_ENTRYPOINT_ENABLED` отвечает только за кнопку, но самостоятельно не включает приём. Нужны оба включённых флага для отображения кнопки; `CHAT_INBOX_ENABLED` определяет фактический приём сообщений. По умолчанию оба флага выключены в `.env.example`, Compose и настройках приложения. Не запускайте дополнительный polling с тем же токеном.

## Исходящие вложения

Загрузка фото, документов и OGG/Opus voice выполняется через `POST /api/admin/conversations/{id}/attachments` с `Idempotency-Key`; отправка в Telegram происходит отдельно в существующем worker. Файлы остаются в именованном Docker volume `chat_staging` до отправки либо конечной ошибки. Volume необходимо сохранять при обновлениях и рестартах — удаление volume приведёт к потере ожидающих отправки файлов.

Максимальный размер файла — 20 MiB, фотографии — 10 MiB; для Nginx установлен `client_max_body_size 21m` с учётом multipart-полей. Staging ограничен 256 MiB и 1024 файлами. Очистка не удаляет файлы, используемые заданиями `queued/sending`; завершённые удаляются после отправки либо периодической очисткой, оставшиеся без записи в БД — через 24 часа. При исчерпании квоты HTTP API отвечает 507.
